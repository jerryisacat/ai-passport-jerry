# assets/ 规则

本目录放 fork 专用二进制素材：启动器、玩法和设备端工具使用的字体、图片与音频。上游可复用素材仍放在仓库根 `assets/`；这里的是我们自己的。

## 布局与命名

- `fonts/`、`images/`、`audio/`。没有第二个文件佐证前，不新建其他顶层目录。
- 文件名使用 lowercase-kebab，并在名称中带变体，例如 `launcher-title-20.bin` 或 `ok-click.wav`。
- 生成文件与来源放在一起：字体的授权和转换命令放在字体旁边，不要只留在某个人的记忆里。

## 来源记录

每个素材都在 [`README.md`](README.md) 中登记（添加第一个素材时建立中英配对）：

- 来源 URL、作者或字库名、授权，并说明该授权允许在本仓库再分发。
- 转换器或工具名称与版本，以及使用的完整命令。
- 字符集或尺寸、采样率、声道、位深等决定输出的参数。
- 提交二进制的校验和，便于比对重新生成的文件。

授权无法核实的素材不得提交。

## 字体

- 目标为 LVGL 9.5 与 `dependencies.lock` 固定的版本。
- 优先按 UI 实际使用的字号做子集，而不是嵌入整个字族。
- 对每个必需码点用 `lv_font_get_glyph_dsc()` 验证字形覆盖；占位符不算覆盖。把测试过的字符集记录到 [`../docs/`](../docs/AGENTS.zh_CN.md) 或使用该字体的应用说明中。
- 授权允许时保留源字体；否则记录来源与重新生成子集的方法。

## 图片与音频

- 屏幕为 240x320 竖屏 RGB565。按实际摆放尺寸制作图片，避免放不进 RAM 预算的全屏缓冲。
- 音频必须匹配 BSP codec 与 I2S 配置；记录采样率、声道与格式。没有明确授权不得随附受版权保护的音乐。
- 不得包含凭证、设备二维码、个人照片或未脱敏截图。

## 文档

- 二进制素材不得与 Markdown 混放。本目录的 README 是登记账本；设计说明放在 `../docs/`。
- 账本与其他维护中的 Markdown 一样，必须是中英配对文档。
