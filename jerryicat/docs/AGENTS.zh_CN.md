# docs/ 规则

本目录记录本 fork 产品如何设计以及为什么这样设计。它是 fork 私有文档，不是上游指南的副本。

## 这里放什么

- 启动器、共享 UI 套件和应用生命周期的架构说明。
- 超出目录 `AGENTS.md` 篇幅的玩法与设备端工具规格。
- 产品决策、取舍、数据格式，以及重置/版本规则。
- fork 固件的真机测试记录：构建标识、观察到的现象、仍未验证的事项。

上游硬件、BSP、工程与协作规则留在 `../../docs/`；需要时链接过去，不要复述。

## 语言与结构

- 英文放 `name.md`，简体中文放 `name.zh_CN.md`，两个文件顶部都有互相切换的语言链接。
- 文件名 lowercase-kebab；一篇文档一个主题。不要为每个页面或每次提交建文档。
- 每篇文档都登记到 [`../README.md`](../README.md) 或文档索引中；文件移动时同步更新链接。
- 图表优先使用文本（ASCII 或 Mermaid）；只有确有必要时才用渲染图片，二进制图片放 `../assets/`。

## 写作规则

- 说明决策、背后的约束，以及它防止的失败模式。不要写调试日记或临时笔记。
- 测试记录要写出准确的构建标识和真机观察；推断要标明是推断。
- 不得出现凭证、设备秘密、个人数据、私有 URL 或未脱敏日志。
- 两种语言必须在同一次改动中保持一致，不得让一侧漂移。
