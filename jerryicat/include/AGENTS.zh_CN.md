# include/ 规则

本目录放启动器、玩法、设备端工具与 `main/` 相互调用所需的公开头文件。这里的内容都是契约，实现位于 `../src/` 或各应用目录。

## 这里放什么

- `main/main.c` 使用的启动器入口 API。
- 设备端应用接口：描述符、类别和生命周期回调。
- 被多个目录使用的共享 UI 套件和运行时辅助声明。

不放别的。只被一个 `.c` 使用的头文件应放在该 `.c` 旁边。

## 约定

- 文件名 `jerryicat_<topic>.h`；include guard 使用 `JERRYICAT_<TOPIC>_H`。
- 公开符号使用 `jerryicat_` 前缀；公开类型以 `_t` 结尾。
- 头文件自包含：用到什么就包含什么，不透明类型用前置声明。不得依赖包含顺序。
- 能用普通 C 类型表达时，不要把 LVGL 和 ESP-IDF 类型放进公开签名。应用回调应接收按键事件，而不是 `lv_obj_t *`。
- 不在这里放板级常量——引脚、地址和屏幕参数只放在 `components/bsp/include/bsp_pins.h`。
- 头文件中不写日志、不做内存分配、不定义静态状态。

## 文档要求

每个声明都要说明用途、参数、返回值和失败值、内存所有权、任务上下文、阻塞行为，以及调用方是否需要持有 `bsp_lvgl_lock()`。应用接口还要说明调用顺序，以及由谁在 `exit` 前停止异步工作。

## 修改接口

应用接口是 `../plays/`、`../apps/` 和启动器共用的契约。修改接口时，必须在同一轮更新所有实现以及描述该接口的目录 `AGENTS.md`。不得为某一个应用另起一套并行接口。

## 验证

头文件由固件构建和包含它的 host tests 验证。即使只改头文件，也要运行 `./tools/validate.sh --static`。
