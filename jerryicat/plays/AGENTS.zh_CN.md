# plays/ 规则

每个玩法都是面向用户的游戏或体验应用。一个玩法一个目录，目录名就是应用 id。

## 目录契约

- 目录名与应用 id 是同一个唯一的 lowercase-kebab 字符串，例如 `snake-run`。
- 每个玩法目录都包含自己的 `AGENTS.md` 与 `AGENTS.zh_CN.md`。该文件说明玩法的定位、页面与流程、操作、状态与持久化、后台任务、退出清理、失败状态、测试计划和真机检查。
- 实现放在玩法目录内。只有第二个应用也需要的代码，才移入 `../include/` 与 `../src/`。

## 接口与注册

- 实现 `../include/` 中的共享设备端应用接口，并在 `../src/` 的启动器表中注册。未注册的玩法就是死代码。
- `id` 与目录名一致；启动器标题要能放进屏幕，并允许本地化。类别为 `play`。
- `enter` 建立玩法页面并重置状态。`exit` 在工作停止后删除页面。可选的 `start`/`stop` 包住工作任务与 I/O。
- 启动器保留 `OK` 长按作为返回手势；玩法决定短按导航和额外手势，不继承基线 demo 菜单的单击/长按契约。

## UI 与硬件规则

- 自行设计玩法的页面、布局和视觉语言。上游 demo 菜单、`demo_*.c` 页面和 `ui_pixel` 外壳只作参考。
- 屏幕为 240x320 竖屏，三个按键（`UP`、`DOWN`、`OK`）。控件和标签要清晰可辨，默认在右上角显示电量，并处理读值为 `-1` 的不可用情况。
- 启动器调用 `key` 时不持 LVGL 锁：更新控件前先取 `bsp_lvgl_lock()`，并保持临界区短小。音频、存储和网络放到工作任务。
- `exit` 前停止所有可能触达玩法 UI 的任务、定时器、回调和事件处理器，并释放音频、网络和存储资源。
- 玩法空闲时调暗或关闭背光；流程允许时回到 light sleep 或 deep sleep。
- 中文文案必须遵循根 `AGENTS.md` 的字体检查清单；UTF-8 字符串不能证明字形覆盖。

## 状态与持久化

- 状态留在玩法内部，不向其他应用暴露可变全局变量。
- 使用 NVS 时放在玩法自己的 key 命名空间下，写明 key 名称、版本，以及过期或损坏数据如何重置。
- NVS 和日志中不得出现凭证、设备秘密或个人数据。

## 测试与文档

- 把纯逻辑（计分、棋盘状态、计时、布局计算）放进普通 C 模块，并在 `../tests/` 中脱离 ESP-IDF/LVGL 测试。
- 在启动器表中添加条目，把源文件加入 `jerryicat/CMakeLists.txt`，并在玩法的 `AGENTS.md` 中写简短的真机测试清单。
- 运行上游门禁与 fork 测试，主动询问真机测试，并按根目录维护规则在 `main` 上提交。

## 命名

- C 文件 `play_<name>_<topic>.c`，公开符号 `jerryicat_play_<name>_*`，文件内状态 `s_`。
- 界面字符串放在玩法目录内的一张小表中，便于一眼审查本地化和字体覆盖。
