# tools/ 规则

本目录放开发侧脚本：构建与烧录辅助、素材转换、发布准备，以及支撑 fork 工作流的检查。固件源码不得放在这里。

## 工具契约

- 优先使用 Python 3 标准库。只有在确实更简单时才用 shell，并保持兼容 macOS 与 Linux。
- 每个工具都要有 `--help`，说明用途、输入、输出、副作用和示例。成功返回 `0`，可处理的失败返回 `1`，用法错误返回 `2`。
- 路径以仓库根为基准解析，不依赖当前目录。不得假设调用方的工作目录。
- 可确定复现、可安全重复执行。相同输入运行两次结果一致，不会重复施加改动。
- 工具没有明确说明时不得交互式提问；破坏性操作提供显式的 `--yes`。
- 构建产物写入 `build/` 或文档说明的临时目录。不得提交生成物、固件镜像或日志。

## 安全

- 源码、参数、环境默认值和输出中不得出现凭证、token、设备秘密、私钥、个人数据或原始设备日志。
- 默认不联网。需要下载的工具必须在 `--help` 中说明，使用 HTTPS，并固定或校验下载内容。
- 破坏性操作必须打印解析后的绝对目标并要求确认。
- 不得修改上游 `tools/`；改为调用 `../../tools/validate.sh` 或对应上游脚本。不得通过在本目录重写来削弱检查。

## 测试与文档

- 任何解析、规划或转换逻辑，只要不是外部命令的薄封装，都要在 `../tests/` 中添加 host test。
- 每个工具都要登记到 [`../README.md`](../README.md) 的表格或自己的 README 配对中，写明一行用途和示例。
- 工具进入标准门禁时，接入本目录的 `validate.sh`，并在根 `AGENTS.md` 中记录新命令。

## 命名

- 脚本使用 lowercase-kebab 名称，例如 `flash-device.py`。
- 共享辅助放在脚本旁边的小模块中；第二个工具需要之前不要先搭框架。
